Cloud Architecture
AWS Multi-VPC Architecture

Built a production-grade multi-VPC architecture with proper isolation, load balancing, and secure communication patterns. This wasn't a tutorial — it was learning by doing, understanding each component's role.

Key Highlight: VPC Peering with route tables configured on both sides, allowing private subnets to communicate securely without exposing anything to the internet.
Tech Stack
AWS VPC VPC Peering ALB/NLB EC2 Node.js Nginx

Architecture Details:

  • Frontend VPC (10.0.0.0/24): Public ALB + Private EC2 with Nginx reverse proxy
  • Backend VPC (192.168.0.0/24): Private NLB + EC2 running Node.js API behind PM2
  • Security: Isolated security groups per layer, SG-to-SG rules, SSM VPC endpoints for bastion-less access
  • Cost Optimization: NAT Gateway created only when needed, deleted after updates

Key Technical Achievements

VPC Peering Configuration

Set up bi-directional VPC peering with proper route table entries and security group rules allowing inter-VPC communication while maintaining strict isolation.

Load Balancer Strategy

Implemented ALB in frontend for HTTP/HTTPS handling and NLB in backend for ultra-low latency API communication. Each optimized for its specific use case.

Security Hardening

Zero exposed instances. All EC2 instances in private subnets accessed via SSM without bastion hosts. Tight security group rules following least privilege principle.

Cost Consciousness

Lifecycle-managed NAT Gateway — only created during necessary operations, deleted immediately after. Demonstrates understanding of cloud economics.
